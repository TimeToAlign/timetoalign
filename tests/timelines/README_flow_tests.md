# Flow API Test Suite - Design and Rationale

## Overview

This document describes the test design for the Flow API (Phase 3.7), which computes unfolded measure sequences from flow control data (repeats, voltas, D.S., D.C., etc.).

## Test Philosophy

### ZERO TOLERANCE Validation

Following the project's engineering standards (AGENTS.md Section 3.6), all tests use **exact value comparisons** against gold standard data:

- **EXACT** row counts (no ranges or minimums)
- **EXACT** `mc_playthrough` sequences
- **EXACT** `mn_playthrough` values with suffixes
- **EXACT** `quarterbeats` values

Any mismatch indicates a bug that must be fixed, not tolerated.

### Gold Standard Source

The gold standard for validation is the **ms3 unfolded TSV files**. These files are generated by the ms3 library (DCML) and represent the canonical unfolding behavior that TTA must match.

Unfolded TSV files contain additional columns:
- `mc_playthrough`: Monotonically increasing index (1, 2, 3, ...)
- `mn_playthrough`: MN with occurrence suffix ("1a", "1b", "2a", ...)

## Test Specimen Roadmap

Tests are organized by **complexity order**, starting with the simplest case and progressing to edge cases:

| # | Specimen | Folded | Unfolded | Flow Control | Status |
|---|----------|--------|----------|--------------|--------|
| 1 | `rachmaninoff_concerto2` | 374 | 374 | None | **PASSING** |
| 2 | `flow_control/polyrhythm_only` | 14 | 14 | Line breaks | Not tested |
| 3 | `couperin/c05n05_musete` | 58 | 138 | D.S. al Fine | **PARTIAL** |
| 4 | `couperin/c11n08_Rondeau` | ~37 | ~100 | Rondeau form | Not tested |
| 5 | `beethoven_op18_flow` | 227 | ~291 | Repeats + Voltas | Not tested |
| 6 | `beethoven_woo71` | 397 | 505 | Complex split bars | Not tested |
| 7 | `flow_control/flow_only` | 15 | 30 | D.S./D.C. al Coda/Fine | Not tested |

### Why This Order?

1. **Example 1 (Rachmaninoff)**: Baseline with NO flow control. If this fails, the basic algorithm is broken. The unfolded sequence should be identical to the folded sequence (ratio 1.0).

2. **Example 2 (polyrhythm_only)**: Minimal flow control (line breaks only, which don't affect traversal). Tests that structural markers don't incorrectly trigger jumps.

3. **Example 3 (Musete)**: First "real" flow control with D.S. al Fine. Tests backward jumps to named markers (Segno) and conditional termination (Fine).

4. **Example 4 (Rondeau)**: Rondeau form with multiple couplets. Tests repeated D.S. patterns within a single piece.

5. **Example 5 (Beethoven Op18)**: Repeats with volta brackets. Tests the volta model (measure attribute, not separate flow control type).

6. **Example 6 (WoO71)**: The "hard case" from the MeasureMap paper. Complex split bars, multiple endings, irregular durations.

7. **Example 7 (flow_only)**: Deliberately complex edge cases. All flow control types in one small piece.

## Test Structure

### Unit Tests

Located in `TestFlowStep`, `TestFlow`, `TestFlowMode`, `TestFlowController`:

- **FlowStep**: Creation, immutability, serialization
- **Flow**: Empty flow, simple flow, flow with repeats, DataFrame conversion
- **FlowMode**: All enum values exist
- **FlowController**: Suffix generation algorithm

### Integration Tests

Located in `TestExample1Rachmaninoff`, `TestExample3CouperinMusete`, etc.:

Each example has three test levels:

1. **test_load_measures**: Can we load the folded TSV?
2. **test_compute_flow**: Does the flow have correct counts?
3. **test_flow_matches_unfolded_gold_standard**: EXACT match against ms3 output

### Mode Tests

- **TestPrintedMode**: PRINTED mode returns folded count (no unfolding)
- **TestFlowMap**: FlowMap can be created from FlowController

## mn_playthrough Suffix Convention

The suffix follows ms3's convention:

- First occurrence of MN=19 -> "19a"
- Second occurrence of MN=19 -> "19b"
- 26th occurrence -> "19z"
- 27th occurrence -> "19aa"

This is implemented in `FlowController._occurrence_to_suffix()`.

## Known Limitations

### D.S. al Fine Algorithm

The current algorithm follows the `next` field naively using visit counts. This works for simple repeats but doesn't correctly handle:

- Conditional jumps based on D.C./D.S. state
- Fine markers that only activate after D.C./D.S.
- Complex multi-pass structures

The `test_flow_matches_unfolded_gold_standard` for Example 3 (Musete) is **skipped** pending algorithm refinement.

### FlowMap Coordinate Transformation

The `folded_to_unfolded()` and `unfolded_to_folded()` methods are placeholder implementations. Full implementation requires:

- Mapping folded quarterbeats to original MC
- Handling 1:N mapping (folded -> multiple unfolded positions)
- Proper offset calculation within measures

## Adding New Tests

When adding tests for Examples 4-7:

1. Add fixtures for the folded and unfolded TSV paths
2. Create a `TestExampleN*` class following the existing pattern
3. Implement the three test levels (load, compute, gold standard match)
4. Initially skip the gold standard test with `@pytest.mark.skip(reason="...")`
5. Remove skip once algorithm produces exact match
